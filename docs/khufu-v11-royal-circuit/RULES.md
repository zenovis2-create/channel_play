# Khufu V11 Royal Chamber Circuit Rules

## Truth Rules

1. Every segment uses `FACT`, `FACT/HYBRID`, `FACT/DISPLAY`, or `HYBRID` from
   `segment-classification.json`.
2. A factual topology claim does not imply measured scale.
3. Portcullis positions are represented as architectural tracks; V11 assigns no ritual or mechanical
   purpose beyond documented blocking architecture.
4. The stacked chambers are display-only and non-traversable. Their common modern name is
   descriptive, not a claim that V11 proves their engineering purpose.
5. Shaft mouths remain narrow boundary evidence and never become traversal.

## Engineering Rules

1. Additive ownership is mandatory. V10 source meshes and materials are immutable inputs.
2. V10 renderer transitions must be exact, reversible, and validated by asset path.
3. Combined visual meshes use separate named box-collider proxies; no generated mesh collider.
4. Build output is deterministic and idempotent.
5. Root transforms remain identity under the shared map root.
6. No `Light`, `Camera`, `AudioSource`, `ParticleSystem`, `Animator`, or runtime manager is added below
   the V11 root.

## Art Rules

1. Chamber identity comes from proportion, material contrast, ceiling beams, portcullis tracks,
   sarcophagus, and controlled section framing, not visible labels.
2. Interior player views must remain enclosed; cutaway visibility is reserved for evidence cameras.
3. Emissive route accents are subordinate to stone and never recolor the whole scene.
4. The pyramid must retain enough surrounding mass to read as a solid monument.

## Evidence Rules

1. A passing log without the expected terminal token is a failure.
2. Screenshots require fresh timestamps, nonblank pixel statistics, a SHA-256 digest, and manual
   inspection.
3. Completion claims name the exact Unity executable, project revision, scene hash, and test count.
4. Package/import failures are reported separately from map implementation failures.
